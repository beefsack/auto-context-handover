# Decisions

## OpenCode V2 MVP (2026-10-27)

- Target OpenCode 2.1.4 only; local directory package `auto-context-handover`. Native `compaction.auto` stays enabled and unchanged.
- Always-on soft threshold defaults to `"70%"`; accept percentage strings or positive integer tokens, never ratio numbers. Override precedence: agent, provider/model, model, global. Resolve the active request model's catalog input limit, else context limit.
- Measure the latest usable assistant's normalized input + cache read/write + visible output + reasoning, then add trailing text at chars/4, including settled tool results. Unknown usage/window fails open. Do not use billing weights or session totals.
- Append short stable nudges to the end of request messages on every over-limit request. Stage offsets default to 0/0.1/0.2 relative to soft; no system-prefix rewrite or persistent nudge. Optional hard ceiling removes every tool except `context_handover`.
- The active model supplies verbatim structured handover text and a short summary. The six-section template preserves critical instructions/scope verbatim or via verified reload paths, runtime controls, explicit vs implicit/adopted decisions, verification provenance, current risks/state, continuation/compaction and predecessor chain, essential snippets, dead ends, and prioritized next steps. Prefer durable docs over repeated background; omit trivia, never unresolved risks or verification distinctions; mark unknowns. `handoverDescription` replaces the template.
- Storage uses the user-authorized fallback B: session-keyed `ctx.storage` KV for full text, links, locks, and experimental loop state; clean on `session.deleted`. No external handover files. A was rejected because complete persisted tool inputs are not reliably recoverable through the server plugin's compaction-filtered context API.
- Direct `read_handover(sessionID)` validates the target session and returns stored text plus link metadata, including child handovers to parents. Mark its result non-truncated to bypass OpenCode's output spill-to-file behavior. Both plugin tools opt out of Code Mode so the hard gate retains a directly callable handover.
- `onHandover.primary` defaults to `new-session`; `lock` is supported. Root successors retain the request model (including variant when known), active agent, and directory, without parentID; an unknown variant uses the default. Check existence, persist links/state, and lock the source before prompting; never fixed-delay creation or interrupt the old run.
- `onHandover.subagent` defaults to `return`: store text, stop-lock the child, and return only summary + child ID + reader hint. Repeat that short reply in subsequent locked requests; never create roots from children. Draft/reset actions are explicitly unsupported in this MVP.
- Backlinks live in successor seeds and KV; forward links live in old-session tool results, a synthetic notice, and KV. TUI automatic following is deferred; desktop/web behavior is out of scope.
- EXPERIMENTAL loop guard: exclude the first root handover; carry consecutive unproductive successor counts across rotations, reset after >=25% of soft estimated added tokens, and lock after three. Warn when the full seed estimate exceeds 50% of soft. Use pre-call snapshots/high-water marks to avoid counting the handover itself; unknown baselines skip counting. It remains approximate, particularly with large fixed prompt overhead or immediate handovers.
- Rollover errors preserve the text and expose the successor ID and lock state. Same-process retries reuse partially created successors; uncertain prompt admission after locking requires user recovery. Crash atomicity between create and link persistence is not guaranteed.
- Call `context_handover` only after the plugin's context-limit nudge or an explicit user handover request, never as normal task completion; once nudged, finish the current unit of work first. This is wording guidance only, not dynamic tool hiding or early-call rejection; `handoverDescription` still replaces the default wholesale.

## Project name (2026-10-27)

- User chose `auto-context-handover` after an originality check; package name and plugin id use it, while tool names `context_handover` and `read_handover` stay unchanged. Keep the existing repository directory until the user renames it. The id change makes prior plugin-namespaced KV handovers, links, locks, and loop state inaccessible; this test-data loss is accepted, with no migration.
