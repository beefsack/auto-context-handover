# Decisions

## OpenCode V2 MVP (2026-10-27)

- Target OpenCode 2.1.4 only; local directory package `auto-context-handover`. Native `compaction.auto` stays enabled and unchanged.
- Always-on soft threshold defaults to `"70%"`; accept percentage strings or positive integer tokens, never ratio numbers. Override precedence: agent, provider/model, model, global. Resolve the active request model's catalog input limit, else context limit.
- Measure the latest usable assistant's normalized input + cache read/write + visible output + reasoning, then add trailing text at chars/4, including settled tool results. Unknown usage/window fails open. Do not use billing weights or session totals.
- Append short stable nudges to the end of request messages on every over-limit request. Stage offsets default to 0/0.1/0.2 relative to soft; no system-prefix rewrite or persistent nudge. Optional hard ceiling removes every tool except `context_handover`.
- The active model supplies verbatim structured handover text and a short summary. The six-section template preserves critical instructions/scope verbatim or via verified reload paths, runtime controls, explicit vs implicit/adopted decisions, verification provenance, current risks/state, continuation/compaction and predecessor chain, essential snippets, dead ends, and prioritized next steps. Prefer durable docs over repeated background; omit trivia, never unresolved risks or verification distinctions; mark unknowns. `handoverDescription` replaces the template.
- Storage uses the user-authorized fallback B: session-keyed `ctx.storage` KV for full text, links, locks, and experimental loop state; clean on `session.deleted`. No external handover files. A was rejected because complete persisted tool inputs are not reliably recoverable through the server plugin's compaction-filtered context API.
- Direct `read_handover(sessionID)` validates the target session and returns stored text plus link metadata, including child handovers to parents. Mark its result non-truncated to bypass OpenCode's output spill-to-file behavior. Both plugin tools opt out of Code Mode so the hard gate retains a directly callable handover.
- `onHandover.primary` defaults to `new-session`; `lock` is the only alternative. Root successors retain the request model (including variant when known), active agent, and directory, without parentID; an unknown variant uses the default. Check existence, persist links/state, and lock the source before prompting; never fixed-delay creation or interrupt the old run.
- `onHandover.subagent` defaults to `return`: store text, stop-lock the child, and return only summary + child ID + reader hint. Repeat that short reply in subsequent locked requests; never create roots from children. Other subagent actions remain explicitly unsupported.
- Backlinks live in successor seeds and KV; forward links live in old-session tool results, a synthetic notice, and KV. The bundled TUI companion now follows successful root rollovers as specified below; desktop/web behavior is out of scope.
- EXPERIMENTAL loop guard: exclude the first root handover; carry consecutive unproductive successor counts across rotations, reset after >=25% of soft estimated added tokens, and lock after three. Warn when the full seed estimate exceeds 50% of soft. Use pre-call snapshots/high-water marks to avoid counting the handover itself; unknown baselines skip counting. It remains approximate, particularly with large fixed prompt overhead or immediate handovers.
- Rollover errors preserve the text and expose the successor ID and lock state. Same-process retries reuse partially created successors; uncertain prompt admission after locking requires user recovery. Crash atomicity between create and link persistence is not guaranteed.
- Call `context_handover` only after the plugin's context-limit nudge or an explicit user handover request, never as normal task completion; once nudged, finish the current unit of work first. This is wording guidance only, not dynamic tool hiding or early-call rejection; `handoverDescription` still replaces the default wholesale.

## Live verification (2026-10-27)

- OpenCode 2.1.4 honors deletion from the context hook's tool record: an isolated hard-limit request exposed only `context_handover`, and its model-authored handover completed. This settles the earlier research's partial tools-off grade; it does not establish an execution-time deny or run-abort primitive.
- Isolated live roots rotated with forward/back links and retained the `default` variant. Separate checks observed the >50%-of-soft seed warning and a root followed by exactly three unproductive successors, with the third locked and no fourth created. Loop checking used a larger absolute soft threshold with short exchanges so fixed prompt/tool overhead stayed below 25% of soft; large transcripts are unnecessary.
- Primary locked-request guidance prescribes a refusal containing the source session ID and a `read_handover` hint for another session. Appending an advisory reader hint alone did not survive model paraphrasing in a live check; prescribing the refusal did. Child return replies remain unchanged. This remains model-facing guidance, not deterministic output interception.

## Project name (2026-10-27)

- User chose `auto-context-handover` after an originality check; package name and plugin id use it, while tool names `context_handover` and `read_handover` stay unchanged. Keep the existing repository directory until the user renames it. The id change makes prior plugin-namespaced KV handovers, links, locks, and loop state inaccessible; this test-data loss is accepted, with no migration.

## Automated handover scope and restored loop fallback (2026-10-27)

- Remove the interactive primary review action, its KV pause state/cleanup, review-only hook, and readback status. It conflicts with the automated direction of the tool. The implementation remains in git history at `a7f77ad` if needed later. Leftover configuration selects an unsupported action and fails setup with the allowed values `new-session` and `lock`; it is never silently converted. Old pause records are no longer read or maintained; stored handover text remains readable.
- Restore the loop guard's `lock` fallback after three unproductive successors. Preserve the final streak and predecessor link without creating another root; measurement and productivity rules are unchanged. The restored fallback and storage failures have unit coverage, not a new isolated live check.
- Shelve subagent `reset`: low value relative to live-verified `return`, which also better fits the principle of deferring to parent agents. OpenCode 2.1.4 `19d87a7` can apply a stale held summary under `experimental.background_compaction` without invoking the compaction hook (`packages/core/src/session/compaction.ts:301-321,395-418`), and exposes no public invalidation API. Future baseline: `session.compact` plus the compaction hook supplying the verbatim model-written handover with `metadata.keepID: null`; do not ship that path without resolving the background-summary bypass. Full investigation: `docs/changes/archive/subagent-reset.md`.
- The deferred TUI companion is follow-rollover only: no review or interactive UI.

## Per-child soft-limit marker (2026-10-27)

- A parent may start a new child's spawn prompt with `[auto-context-handover-test soft=4096]`, using whitespace-separated `key=value` pairs. Implement only `soft`, in the same positive-integer or percentage formats as configuration; reject unknown keys, duplicate keys, malformed pairs and invalid values explicitly rather than ignoring them.
- Parse in `session.prompt` before admission, only at the start of an initial real-child prompt, allowing the standard subagent banner. Await session-keyed KV persistence before stripping the marker. Never scan root prompts, quoted material, tool results or later history.
- The stored child override outranks agent/model/global soft settings without changing hard limits, nudge staging or child return. It survives reload and compaction, is removed on `session.deleted`, and is not inherited by descendants or successors. No configuration edit or restart is required. Usable assistant usage remains necessary for a nudge, so checks need at least two model turns.
- Live verification after clean plugin loading confirmed the marker was stripped from admitted text, the child reported the exact plugin nudge, one handover call returned only the short summary/reader hint, and parent readback recovered the full text. Reload/compaction persistence, deletion, strict rejection and non-inheritance are unit-tested, not additionally live-tested.

## TUI rollover following (2026-10-27)

- Bundle a conventional root `tui.ts` entry beside `index.ts`, preserving server entry resolution and loading both parts from the existing `plugins` entry. No separate install, config key, dependency, JSX, or interactive UI. OpenCode 2.1.4 `19d87a7` resolves these entries in `packages/plugin/src/host.ts:25-64`; the public V2 [plugin guide](https://opencode.ai/v2/docs/build/plugins) documents automatic companion loading.
- Add `metadata["auto-context-handover"] = { successorID }` only to successful root-rollover tool results, after successor existence, links, source lock and prompt admission are established. Subscribe to `session.tool.success`, not human-readable text or server KV. The pinned success event carries result metadata (`packages/schema/src/session-event.ts:534-548`, `packages/core/src/session/runner/publish-llm-event.ts:608-624`); no custom RPC is needed.
- Require the current TUI route to show the source both at event receipt and immediately before navigation. Verify the successor with `client.session.get`, coalesce duplicate in-flight signals, and cancel pending follows on disposal. Unavailable successors and lookup failures are silent no-ops, with no fixed delay. Pinned TUI APIs: `packages/plugin/src/tui/context.ts:63-87,142-152,496-500`.
- Follow live events only; do not redirect historical-session visits or backfill missed events. Lock mode, child return, loop-guard stops and unsuccessful rollovers emit no follow hint. Desktop/web remain out of scope.
- Verification: unit tests cover metadata, navigation guards, lookup failures, duplicates and cleanup. An isolated real OpenCode 2.1.4 TUI imported the production companion and logged successful `auto-context-handover-tui` setup without any prompt or model call. End-to-end rollover navigation remains an interactive manual check, not live-verified.
