# OpenCode V2 handover MVP

- Goal: a lean locally installable context-handover plugin for OpenCode 2.1.4; no commits or pushes.
- Governing scope: docs/principles.md and the user-approved design in the task. Native auto-compaction stays enabled; no paid model calls.
- Acceptance: staged per-request soft nudges, optional hard gate, active-agent-written handover, primary root rollover/lock, subagent return, read_handover(sessionID) and bidirectional session links, experimental progress loop guard, installation/config/manual-test README, typecheck and pure-logic tests.
- Optional: draft/reset and minimal TUI following only if inexpensive; otherwise report explicit deferrals.
- Plan: (1) investigate sanctioned storage and exact runtime contracts; (2) implement bounded core/plugin unit and tests; (3) independent contract review and verification; (4) durable decisions and archived outcome.
- Storage: user authorized A preferred, B fallback. A stores full handovers naturally in tool-call input and successor seed; first verify persisted full inputs and cross-session/child reads through plugin API. If unreliable, B stores verbatim handover text in session-keyed ctx.storage KV. Both use read_handover(sessionID); no external files. Small state uses KV with session.deleted cleanup.
- Delegation: foreground Workers, one at a time. Workers do not maintain project records or edit existing research/principles/backlog.
- Verification: typecheck, focused unit tests, no-model-call plugin-load smoke test if available; inspect actual changes and evidence.
- Initial state: repository contains untracked user docs; preserve them. No repo AGENTS.md.
- Blocked at storage gate: pinned source verified at `19d87a72e6da026cc3f0cc620808d336d9fb0a04`. `ctx.storage` exposes JSON KV only (`packages/plugin/src/promise/storage.ts:4-9`), backed by namespaced database keys (`packages/core/src/plugin/host.ts:654-681`, `packages/core/src/kv/sql.ts:5-9`). Plugin context exposes no sanctioned filesystem data path (`packages/plugin/src/effect/plugin.ts:26-55`). Sessions also live in SQLite, not session directories. `session.deleted` is published (`packages/core/src/session.ts:396-405`), but plugin KV cleanup must be explicit.
- Initial storage-gate evidence: Lead inspected the source references above and verified the checkout HEAD. At that point only this change note was added; existing user docs were preserved.
- Storage blocker resolved by the user authorization above. Parent return summaries contain the child session ID and read_handover instruction rather than a path; successor seeds link the source session ID and read_handover.
- Storage A checked: completed tool inputs are untruncated records (`packages/schema/src/session-message.ts:148-154`), but server plugins expose only compaction-filtered `session.context`, not full message history (`packages/plugin/src/promise/session.ts:154-175`; `packages/core/src/session/history.ts:149-179`). Child access is not the blocker; history loss from the exposed read window is. Authorized fallback B selected: capture verbatim text in session-keyed KV at handover execution; read_handover reads KV after validating the session exists. No external files.
- Initial implementation produced root package/shim, source modules/tests, README, and lockfile. Worker reported typecheck and 33 passing tests plus isolated host activation; not accepted as completion.
- Independent contract review found integration gaps: loop streak not inherited, successor admitted before source lock/state, late duplicate guard, swallowed KV writes, unstable within-stage nudge numbers, flat action config and nonfunctional reset, stale session model use, inconsistent seed estimates, no child stop lock, and missing manual test plan. These are corrections to the decided design, not design changes. Pure helper tests alone did not establish integration correctness.
- Runtime contract accepted: deleting context hook tool definitions affects dispatch (`packages/core/src/session/model-request.ts:264-298`); appending Message.system to event.messages is a chronological operator update, distinct from event.system. Published 2.1.4 imports use @opencode/ai root rather than the checkout's /effect path.
- Recovery corrections: shared readiness/link/state/lock path now runs for fresh and reused successors; source loop state advances only after locking; strict tool-path KV reads reject outages; child stop locks repeat the short parent reply. Setup-local maps prevent instance leakage and cleanup aborts the event subscription. Regression tests cover partial writes, retries, inherited loop streaks, and productive reset.
- Additional accepted runtime evidence: default tool registration is Code Mode only (`packages/core/src/tool.ts:260-263`), so both tools are explicitly direct. Long normal tool results spill to files (`packages/core/src/tool-output.ts:69-118`); direct read_handover returns `metadata.truncated:false` to preserve full reads without external files. Tests cover routing and >50 KiB / >2000-line handovers.
- Final files: root index.ts/package.json/package-lock.json/.gitignore, source/{index,config,measure,store,text}.ts, source/{config,measure,gate}.test.ts, source/tsconfig.json, README.md, docs/decisions.md, this archived note. Existing principles/backlog/research unchanged.
