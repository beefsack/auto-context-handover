# Qwen Code adapter assessment

- Goal: establish a pinned Qwen Code measurement, injection, identity and packaging contract; implement the smallest useful adapter only if that contract supports model-authored pre-compaction handover.
- Scope: official documentation and installed-package evidence, shared guidance reuse, isolated non-model validation, unit coverage and concise installation/research records. Native compaction stays unchanged.
- Acceptance: defensible measurement plus attributed writer/reader and continuation; prefer native children when measurable and identifiable. Typecheck, full tests, existing Claude plugin validation, Qwen packaging/MCP checks and independent contract review. Documentation distinguishes fixtures, observed non-model behavior and unverified model compliance.
- Approach: assess pinned hooks, storage, MCP and subagent delivery first; implementation depends on that evidence. If blocked, retain a concise capability assessment and exact unblock path instead of a speculative adapter.
- Outcome: subagent-first adapter implemented for Qwen Code 0.26.3. Native classic-hook extension and MCP reuse shared guidance/stages and unchanged Codex storage/capability code; roots context/read-only. Latest child transcript response usage is synchronously recorded before tools; integer soft only, no borrowed root window or Stop telemetry.
- Material decisions: separate linked extension/intact checkout, host-bound single-use original arguments, immutable model text/closure, advisory parent reference continuation, no hard token gate/root rotation. Tentative entries promoted to `docs/decisions.md`; sources/limits in `docs/research/qwen-code.md`, checklist in `docs/adapters.md`.
- Review: independent contract/security inspection verified whole-input replacement/MCP capability dispatch and identified unbound reader bypass, duplicate/mislabelled batch notices, invalid-soft invention, corrupt-checkpoint/torn-read fallback. Resolved with both-tool binding, PostToolUse only, unknown invalid-config diagnostics and conservative parsing. Checkpoint write loss remains an explicitly documented ordinary fail-open limitation.
- Evidence: final typecheck passed; 753 tests passed, including 45 Qwen fixtures, no failures/skips. Existing Claude plugin validation passed with author/icon warnings. Isolated Qwen link/list and host MCP connection succeeded; SDK stdio listed both tools and refused both unbound calls. Manual spaced-path/foreign-cwd probes produced valid JSON/capabilities. Fixture corrections repaired stale assertions after the reviewed contract changes; no production workaround for a failed host fixture.
- Limits: no real child hook firing, model compliance, receipt or end-to-end successor continuation established. Unknown child windows, native compaction precedence, no lineage/original capture/automatic spawn, no retention quota/fsync/same-user sandbox guarantees. No unresolved serious review findings.
