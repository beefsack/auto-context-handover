# OpenCode latest-version support

- Goal: migrate the V2 adapter to the latest published OpenCode plugin API and remove the temporary 2.1-only compatibility exception.
- Scope: assess the used API surface, minimally adapt source/tests, widen package and public compatibility ranges, and document exact assessed versions as evidence. Preserve existing lifecycle, threshold, storage, variant and TUI behavior; no new product behavior.
- Acceptance: latest published types pass typecheck and regression tests; the migrated entry remains loadable on the installed release; all used API changes have source evidence and handling. Public ranges use major or major.minor constraints, never patch versions.
- Approach: investigate the published API and upstream source, implement the minimal migration with targeted regressions, then independently review the compatibility contract and verify the final tree.
- Units: API investigation; implementation and fixtures depending on that assessment; independent migration review; final verification and records.
- Verification: `npm run typecheck`, `npm test`, source/API comparison, non-model plugin load checks, and diff checks. Model-driven continuation, gating and TUI navigation remain unverified by this migration.
- Initial evidence: npm reports `@opencode/ai` 2.2.5 as latest; the installed OpenCode reports 2.2.5. Existing package ranges are `~2.1`.
- Migration: AI/schema/plugin ranges are now `>=2.2 <3`; `Message` comes from `@opencode/ai/effect`. The root export is absent in 2.2.0-2.2.3 and restored in 2.2.4-2.2.5; the Effect entry and `Message.system` work in both 2.2.0 and 2.2.5. The 2.1.4 package lacks this entry and is no longer supported.
- Dependency finding: the first migration typecheck failed with direct Effect 4.0.1 alongside OpenCode's 4.0.6 schema types. Changing the direct dependency to `^4` resolved a shared 4.0.6 and passed typecheck. No product workaround was needed.
- API assessment: compared published 2.1.4 and 2.2.5 plugin `dist/promise/adapter.js` and declarations. The used storage get/set/remove and session hook/create/get/prompt/synthetic/context mappings are unchanged. Event subscription adds an optional type filter; this adapter still supplies only its abort signal. Added instructions, artifact/generation and moved experimental wait APIs are unused.
- Schema/TUI assessment: published schema `dist/session-event.js` is unchanged; it retains `session.tool.success` durable version 2 with optional JSON metadata and `session.deleted.data.sessionID`. Session-message changes add opt-in media user schemas without changing assistant token fields; session info adds an optional busy timestamp. Tool inputs, `codemode: false`, `Tool.Error` and result metadata remain compatible. Plugin `dist/tui/context.d.ts` retains the data subscription, session lookup and router APIs used by the companion. No changes to variant forwarding, context tool-record gating or normalized usage fields were required.
- Sources: npm [AI 2.2.0](https://registry.npmjs.org/@opencode/ai/-/ai-2.2.0.tgz), [AI 2.2.5](https://registry.npmjs.org/@opencode/ai/-/ai-2.2.5.tgz), [plugin 2.1.4](https://registry.npmjs.org/@opencode/plugin/-/plugin-2.1.4.tgz), [plugin 2.2.5](https://registry.npmjs.org/@opencode/plugin/-/plugin-2.2.5.tgz), [schema 2.1.4](https://registry.npmjs.org/@opencode/schema/-/schema-2.1.4.tgz), [schema 2.2.5](https://registry.npmjs.org/@opencode/schema/-/schema-2.2.5.tgz); current [plugin guide](https://opencode.ai/v2/docs/build/plugins) and [TUI guide](https://opencode.ai/v2/docs/build/plugins/cli).
- Review evidence: independent migration review found no blocking regression. Isolated OpenCode 2.2.5 with private configuration and model fetching disabled loaded a wrapper importing the production server entry; a marker written only after production `setup` resolved confirmed actual setup during a standalone agent-list API request. No session or model request was created. A plain config inspection and an empty plugin list were not accepted as setup evidence. An initial non-standalone inspection hit an occupied managed-service port; the isolated standalone check avoided it without modifying that service.
- Verification boundary: existing fixtures cover effective variant carry-over, root rollover, lock fallback, loop guard, hard ceiling, per-child markers, child return and TUI follow. No new fixtures were needed for the import-only production change. The 2.2.0 boundary checks cover the constructor/export, not a full host run or full test matrix. TUI host setup, live gating/model compliance, nondefault end-to-end effort and rollover navigation remain unverified on 2.2.5; historical live evidence is unchanged.
- Final verification: `npm run typecheck` passed across all configured adapters; `npm test` passed 763 tests in 140 suites, 0 failures/skips; `git diff --check` passed. Dependency inspection confirmed AI/schema/plugin 2.2.5 share Effect 4.0.6. The unchanged root entry forwards to the production server entry tested above.
- Outcome: migration complete within scope; current support and assessment boundaries are reflected in README, root guidance and decisions. The installed 2.2.5 host remains supported and its isolated server setup succeeded. No product behavior was changed; future live model checks require separate evidence.
