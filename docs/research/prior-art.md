## 1. Summary: takeaways and adapter priority

The closest full loop is claude-auto-handoff ([repo](https://github.com/alexknowshtml/claude-auto-handoff)): measured threshold, warn, hard tool gate where a refused call always ends in a handover, 40k seeded headroom floor, max-2 unattended handoffs, brief plus chain-linked viewer pages. Its authorship differs from the target: a Haiku sub-model writes the brief, not the active agent. No surveyed project covers the exact combined target (measured soft threshold + warn + hard tools-off turn + active-agent structured handover + lock/new/return policy with old ID + transcript pointer). Partial active-agent precedents: oc-ctx-handover (active agent writes HANDOVER.md, in-place reset via compaction, [repo](https://git.sync.wtf/troed/oc-ctx-handover)); opencode-handoff (model drafts continuation prompt in the active session, editable review, new session, [repo](https://github.com/joshuadavidthomas/opencode-handoff)); token-norm (pause-time skeleton note the agent completes, [repo](https://github.com/salitaba/token-norm)).

Measurement precedent converges: anchor on the latest provider-measured assistant message (input + output + reasoning + cache.read + cache.write), add a chars/4 estimate for trailing content, resolve the limit from the model catalog, keep an explicit reserve. oc-ctx-handover ([repo](https://git.sync.wtf/troed/oc-ctx-handover)), DCP ([repo](https://github.com/Tarquinen/opencode-dynamic-context-pruning)), omo preemptive trigger ([issue #1346](https://github.com/code-yeongyu/oh-my-openagent/issues/1346)), and Pi `getContextUsage` all do variants of this. Pi exposes a documented estimator API (`getContextUsage`, [extensions](https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/coding-agent/docs/extensions.md)) that anchors on measured usage plus chars/4 and returns null after compaction; estimator coverage in other harnesses was not surveyed to claim uniqueness either way. Two accounting cautions: token-norm's `effectiveFresh` (input + 0.1*read + 1.25*write) is a cost-weighted proxy, not current effective context; and provider fields must be mapped per harness rather than blindly summed, since output/reasoning may overlap depending on the API and cache content counts full toward the window even when discounted in price.

Enforcement precedent splits three ways. Hard tool gates: claude-auto-handoff (deny + must-handoff invariant) and token-norm block mode (opt-in refuse past a hard limit, cheap tools + handoff exempt). Budget cap plus instruction: oc-ctx-handover (maxTokens cap, replace step, max 3 re-instructions, never `interrupt()`). Nudge only, never blocking: DCP. The lesson for the target's warn, gate, handover pipeline is staged escalation with distinct directives: omo's fork demonstrated 70%/76%/78% phases, and claude-auto-handoff's tight-threshold headroom correction (floor + 40k) fixes the recurrent "threshold too tight to write the brief" bug class.

New-session rotation is the sharpest integration risk everywhere. opencode-handoff hit the async `session_new` + `appendPrompt` race ([issue #16](https://github.com/joshuadavidthomas/opencode-handoff/issues/16)); token-norm hit the same root cause and now waits for `session.created` evidence plus a settle floor with a bounded fallback (survey wording; exact fallback target unverified, confirm in source before relying on it). The omo fork achieved rotation via `session.create()` + `session.promptAsync()` and remains blocked on TUI session switching (issue comments in [#1346](https://github.com/code-yeongyu/oh-my-openagent/issues/1346)). Pi session ops are command-context-only by design and no official event-to-`newSession` path is demonstrated. Confirmed session-creation plus UI paths differ per harness and unattended policy differs per client: OpenCode companions can create plus navigate (TUI `ui.router.navigate`, desktop `ctx.tabs.open`, web cannot); Amp has `agent.createThread({show:true})` (active "in supported clients" only); AiderDesk extensions can `createTask`/`forkTask`/`duplicateTask` plus `runPrompt`/`runSubagent` with draft review (no task-switch/select API verified, so extension-driven UI selection is unproven), but automatic threshold-driven rollover is unproven there. Configurable automatic rollover stays in the product intent; per-client confirmation vs unattended behavior is an open question, not a researched impossibility.

Recommended adapter priority, with rationale, no commitment beyond OpenCode: (1) OpenCode V2 first - the only harness where per-request `context` hook, supply-summary compaction hook, and `session.create`/`prompt` are verified in the core baseline; review-dialog claim routing and the lossy `read_session` transcript tool (user/assistant text retained, tool results reduced to first line; default 100 messages, max 500) are plugin-level, demonstrated by opencode-handoff, not built-in core. (2) Claude Code mods second - `turn.step` fires before each model request with per-request `usage`, plus `tool.call`/`tool.check` deny; other per-request gates exist (Gemini `BeforeModel`, Pi `context`/`before_provider_request`), but mods is the in-process JS option with subagent coverage via `e.agentId` ([mods events](https://code.claude.com/docs/en/plugins/mods/events)). Settings hooks alone are insufficient (no BeforeModel). (3) Gemini CLI third (historical as a target, superseded by the [Antigravity CLI assessment](antigravity-cli.md); rows below preserved, not regraded as Antigravity) - `BeforeModel` deny/synthetic plus `BeforeToolSelection` schema filtering is the strongest documented gate of any settings-hook harness ([reference](https://geminicli.com/docs/hooks/reference)), but `PreCompress` is advisory-only so rotation races compression. (4) Pi fourth - estimator plus `tool_call` block plus verified manual command rollover are viable, but automatic event-driven rollover is unproven (command-only session ops) and there is no core subagent primitive. (5) Crush / Copilot CLI / Codex CLI as watch items - each has a deny gate plus a compaction hook, but none has per-request measurement plus programmatic rotation. (6) Defer: Cursor (no per-model gate), Cline VS Code file-hooks (beforeModel is SDK-only), Roo (no hooks), Aider (no extension surface), Goose (tool gate only, no injection), Amp (no usage getter, no per-request hook; thread creation exists but trigger/switch are partial). Exploratory next tier if adapters advance: AiderDesk - its installed-extension API (usage events, `blocked`, `interruptResponse`, `createTask`/`forkTask`/`duplicateTask`, `runPrompt`/`runSubagent`, prompt-template overrides) is richer than first reported, but it is an app-specific model (full app + DB) with no verified extension-driven task-switch API, not a thin adapter, so it stays behind the thin-adapter harnesses.

### 2.3 Tracker, PR, and changelog lessons (highest value)

- opencode-handoff [#16](https://github.com/joshuadavidthomas/opencode-handoff/issues/16) (closed; fixed via [PR #17](https://github.com/joshuadavidthomas/opencode-handoff/pull/17), later superseded by the v2 RPC claim flow per [CHANGELOG](https://github.com/joshuadavidthomas/opencode-handoff/blob/98382953dd86d7a710d4be0d75b12f38192ae79c/CHANGELOG.md)): `session_new` + `appendPrompt` are fire-and-forget; guard `if (!input || input.isDestroyed) return` drops the prompt arriving before input mounts. First fix 150ms delay, superseded by v2 RPC claim + new flow. Lesson: never fixed-delay a session switch; wait for creation evidence plus a settle floor. token-norm independently hit the same race and now waits for `session.created` evidence plus settle floor with a bounded fallback (survey wording; exact fallback target unverified, confirm in source before relying on it).

## 3. Design adopt and avoid, mapped to citations

Adopt:

- Anchor-plus-delta measurement with catalog limit and explicit reserve [OC] [DCP] [OMO]. Adopt oc-ctx-handover's anchor (measured) vs estimate logging, catalog-first limit resolution, and `docRoom`/`WORK_FLOOR` reserve math; DCP's per-model `modelMaxLimits`/`modelMinLimits` keyed by exact `providerID/modelID`; omo's 70/76/78 staged escalation for warn/gate/handover. Mark every number measured or estimated; never sum across branches without message-id dedupe (Claude mods `result.usage` double-count warning). Keep cost-weighted proxies (token-norm `effectiveFresh`) separate from current-effective-context accounting; map provider fields per harness instead of blindly summing output+reasoning (overlap varies by API), and count cache content full toward the window even when price-discounted.
- Supplied-summary compaction and facts-only brief guards [OC] [CAH]. Adopt oc-ctx-handover's fixed `event.result.summary` (avoids [#53242](https://github.com/anomalyco/opencode/issues/53242) empty-summary class) and claude-auto-handoff's real-numbers injection plus `[unverified: not in Handoff Numbers]` marking and facts-only fallback.
- Evidence-gated rotation, visible-session routing, bounded retries [TN] [HO] [OC] [CAH]. Adopt token-norm's `session.created` evidence + settle floor + bounded fallback (root cause shared with handoff [#16](https://github.com/joshuadavidthomas/opencode-handoff/issues/16)); handoff v0.6.1's claim routing to the TUI SHOWING the source session; oc-ctx-handover's max-3-instruction bound plus mtime stale guard plus `handoverInFlight` guard; claude-auto-handoff's refused-call-must-handoff invariant, seeded floor `max(threshold, floor+40k)`, and max-2 unattended cap.
- Active-agent narrative written BEFORE context loss, with deterministic capture as input [SP] [AD] [OMO] [CAH]. The handover author (active agent) writes from live context; deterministic git-state/file capture feeds it, it does not replace it. Delayed LLM enrichment after compaction loses negative knowledge: superpowers-ruby ships hook docs with unenriched markers that the resumed session must fill from already-compacted context [SP]. Prefer AiderDesk's pre-compaction snapshots plus draft-review before the new task starts [AD], and omo `/handoff` verbatim USER REQUESTS AS-IS plus EXPLICIT CONSTRAINTS ordering [OMO]; use Haiku-style facts-only sub-model output at most as a check layer, never as the author [CAH].
- Verification honesty [TN] [DCP]. Adopt token-norm's per-run "not exercised" rows and DCP's fail-closed-on-unevaluable rule ([#636](https://github.com/Tarquinen/opencode-dynamic-context-pruning/issues/636)): if the limit or usage is unknown, suppress action and say so.

Avoid:

- Fixed-delay session switching (handoff [#16](https://github.com/joshuadavidthomas/opencode-handoff/issues/16), token-norm race [TN]). Do not `session_new` + immediate `appendPrompt`.
- Counter-based reminder dedupe (token-norm 61x wallpaper [TN]). Dedupe on message identity; one block, fixed order, latched once per metric.
- "Run X" as advice (token-norm call-79 deferral [TN]). The plugin runs the capture itself and staples the result.
- `interrupt()` to stop the agent on OpenCode 2.1.2 (oc-ctx-handover verified it cancels the queued compaction + continue prompt [OC]).
- Bare tool-spec removal assumptions: deleting tools breaks the prompt-cache prefix on the OpenCode baseline (supplied core fact); Pi `setActiveTools([])` takes effect next turn and the MCP extension can re-add discovery tools; Crush `permissions deny` hides tools but text-only via deny-all is unverified.
- PreCompact `continue` as a block on Claude settings hooks (discarded; block only via exit 2 or `decision:block`); post-limit PreCompact block surfaces the API error and fails the request ([hooks reference](https://code.claude.com/docs/en/hooks)).
- Treating snapshots as rollover. File checkpoints (AiderDesk snapshots, Crush sqlite, Roo shadow-git) are provenance, not rotation. Rollover in this report means new session + seed + UI switch only.
- Copying license-encumbered code: DCP AGPL-3.0 [DCP], omo SUL-1.0 [OMO], Crush FSL-1.1-MIT. Reimplement ideas; do not vendor without review (section 6).

OpenCode V2 baseline used (supplied previously verified, commit `19d87a72e6da026cc3f0cc620808d336d9fb0a04`, v2.1.4): `Plugin.define`; `ctx.session.hook('context')` mutates system/messages/tools per request, not persisted; `ctx.model.list` supplies limits; usage is latest assistant input + cache.read + cache.write plus delta estimate; native compaction runs BEFORE the context hook; `compaction.auto:false` also disables overflow recovery; deleting tools breaks cache prefix; native final step keeps tools with toolChoice none (hook cannot set runner toolChoice); `session.create`/`prompt` auto-start; TUI companion `ui.router.navigate`, desktop companion `ctx.tabs.open`, web cannot; successor is ROOT with explicit backlink (parentID hidden child); subagent final text reaches parent but multi-message finals may deliver last segment only. The oc-ctx-handover cap/replace tactics in section 4 C4 are that plugin's methods, not core baseline primitives; the baseline supplies message/maxTokens mutation only.
