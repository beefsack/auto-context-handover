# Harness reassessment: Amp, Cursor, Cline, Goose, Roo, Aider

Assessment date: 2026-10-29. Scope: minimum viable adapter = any defensible measurement (including lagged, tool-boundary, or estimator) + trusted-ish injection + model-callable handover and reader with durable storage + manual or automatic continuation. No per-model gate required. Verdicts use official docs and pinned packages/source; weaker quick-screen evidence is labelled below. No live model runs, hook firing or continuation observed. This report supersedes the stale defer/watch rows for these six harnesses in prior-art.md sections 1 and 4.1-4.5.

## Cline: feasible via hook-bearing AgentExtension

Subsequent implementation pins official `cline@3.0.74` with SDK `0.2.0` and
observes isolated package install/load; [current assessment](cline.md).
The following screen's CLI-unpinned caveat is historical, not a current blocker.

- Measurement: `beforeModel` receives the complete request; estimator applies `chars/4` over the full request (`systemPrompt`, `messages`, `tools`, `modelTools`) and labels it a heuristic. Usage accumulation semantics are NOT established by the shipped declarations (`usage` on the snapshot, `Partial<AgentUsage>` on `usage-updated` events): usage is not a proven window meter, and per-run `result.usage` deltas MUST NOT be summed as window state ([plugins](https://docs.cline.bot/sdk/plugins), [agent declarations](https://unpkg.com/@cline/shared@0.2.0/dist/agent.d.ts)).
- Injection: `beforeRun`/`beforeTool`/`afterTool` `appendContext` (in-process, no system-priority claim); `beforeModel` message/tool/option replacement is the strongest directive path; `beforeTool` `skip` + `reason` with policy ([plugins](https://docs.cline.bot/sdk/plugins)).
- Tool registration and identity: `api.registerTool` / `createTool`; hook-bearing `AgentExtension` loads from `pluginPaths` file or package installs ([plugin loader](https://unpkg.com/@cline/core@0.2.0/dist/extensions/plugin/plugin-loader.d.ts)). Distinguish from Agent Plugins v1 (`cline hub plugins`: manifest + skills + MCP servers only, no hooks) ([writing plugins](https://docs.cline.bot/sdk/guides/writing-plugins)). CLI installation is documented in the official guide, but the CLI package itself is unpinned here, so feasibility is stated for the hook-bearing extension surface, not a pinned CLI build. Every tool execution receives host-bound identity (`AgentToolContext`: `sessionId?`, `agentId`, `conversationId?`, `runId`, `iteration`, `toolCallId?`, host-set `cwd?`) ([agent declarations](https://unpkg.com/@cline/shared@0.2.0/dist/agent.d.ts)).
- Storage/reader: file storage under session/global paths via host runtimes plus a registered reader tool; no quota/TTL/eviction established.
- Continuation: SDK `cline.start` / headless CLI spawn is programmatic, but no third-party UI-switch API is documented, so posture is manual-follow. VS Code extension file-hook-only route (`.clinerules/hooks/PreToolUse`, `.cline/hooks/PreToolUse.sh`) stays blocked: tool-level only, no usage payload, no per-request hook ([clineignore/hook doc](https://docs.cline.bot/customization/clineignore)).
- Subagents: CLI/Desktop `spawn_agent` with own window and final reply; the VS Code file-hook path has no established child measurement/attribution workflow in this assessment ([plugins](https://docs.cline.bot/sdk/plugins)).

## Amp: feasible advisory-first MVP

Subsequent [Amp implementation and offline-load evidence](amp.md) supersede
this screen's manual-follow posture: source `thread.agent()` can create a fresh
root and append its continuation from successful turn end. Actual authenticated
continuation/client following remain unverified.

- Measurement: no usage/token getter in the shipped declarations ([index.d.ts](https://unpkg.com/@ampcode/plugin@0.0.0-20261028101742-g93a0da1/index.d.ts)); only `CreateAgentConfig.compactionThresholdTokens` (default configured percentage, 90%). Estimator: page default-view `thread.messages()` (what a new inference turn sees) at `agent.start`/`tool.result` boundaries, apply `chars/4` over visible text. `full:true` includes compacted-away history and MUST NOT be counted as the active window. The text-only estimator excludes system prompt, tool schemas, and deferred modules, so it may undercount; it is not a mathematical lower bound ([api](https://ampcode.com/docs/plugin-api)).
- Injection: `agent.start` return `{message}`, `tool.result` handling, `thread.append` / `appendUserMessage` (`steer:true` queueing), `changes.prompt` append; turn/tool granularity only, no per-request hook ([plugins](https://ampcode.com/docs/customize/plugins)).
- Tool registration: `amp.registerTool({name, description, inputSchema, execute})`; `ctx.tools.call` direct calls; every tool execution arrives with its calling thread handle (`PluginToolContext.thread`) ([index.d.ts](https://unpkg.com/@ampcode/plugin@0.0.0-20261028101742-g93a0da1/index.d.ts)).
- Storage/reader: no private per-plugin store in the shipped declarations; concrete shape is handover file + model-callable reader tool over a fixed path plus the documented tagged-template `ShellFunction` shell runner.
- Continuation: `agent.createThread()` returns a thread handle - append via the returned thread's `appendUserMessage`; alternatively one-shot `agent.run(message, {parentThreadID, ...})` on a separate thread (do not conflate the two paths). `show:true` activates the thread only in supported clients (coverage unmatrixed), so posture is manual-follow. `agent.end` `continue` defaults to 5 consecutive plugin continuations (`maxContinuations` configurable; any user message resets the count), not a fixed cap ([plugins](https://ampcode.com/docs/customize/plugins)).
- Compaction: no compaction lifecycle hook, no global disable key.
- Subagents: `createAgent` + `run()` returns `{threadID, text}` with `parentThreadID` linkage; detection by thread-id compare ([api](https://ampcode.com/docs/plugin-api)).

## Goose: conditional MVP only

- Measurement: no usage in hook input - but that is a payload gap, not a hard trigger gap, since an ordinary hook (shell with `session_id` on stdin) can shell out to a read-only lagged read: session export in JSON/YAML (markdown export renders user-visible messages only and omits usage) or the pinned `sessions` table (`usage` = latest per-request provider report, `accumulated_*` = cumulative ledger). Non-model CLI invocation of that export path is NOT observed. Source: `session_manager.rs` (`usage` vs `accumulated_usage`), `crates/goose-cli/src/commands/session.rs:293` (`handle_session_export`) ([session management](https://goose-docs.ai/docs/guides/sessions/session-management), [logs](https://goose-docs.ai/docs/guides/logs)).
- Injection: hooks add no general `additionalContext` channel. The only model-visible paths are denial gates - opt-in intrusive, not an ordinary nudge: `PreToolUse` denial refuses the call with the hook `reason` shown to the model, and turn-end `Stop` denial forces another turn (consecutive-block cap), injecting a user-role message hidden from the user but visible to the model. Safe shape only: turn-end `Stop` denial plus cap; if `PreToolUse` denial is used, exempt the writer/reader tools. Only `PreToolUse` and `Stop` can block; `UserPromptSubmit` / `PostToolUse` blocks are ignored; `SubagentStart`/`SubagentStop` are never emitted ([hooks](https://goose-docs.ai/docs/guides/context-engineering/hooks/)).
- Tool registration: a bundled/std-MCP handover + reader tool pair is viable installed surface, but session leases (`session_id` in the extension manager) do NOT establish caller identity transmitted to an external MCP tool. Design must be conditional root-only binding/setup; never claim API caller binding is proven. Adapter-owned private files via MCP is the simplest storage shape.
- Storage/reader: session DB plus import/export JSON (new ID on import); durable storage exists, machine reader is the to-be-built MCP/file reader.
- Continuation: manual only (resume from history, duplicate full copy, fork-from-message, import/export; CLI/Desktop share one session DB). Hook-spawned successors are not required, and resume/duplicate alone is not fresh context: a manual new root seeded by reader reference to the stored handover is the sufficient continuation shape ([session management](https://goose-docs.ai/docs/guides/sessions/session-management)).
- Subagents: natural-language `delegate`/`summon` with `execution_summary` + `task_results`; no hook lifecycle events ([subagents](https://goose-docs.ai/docs/guides/context-engineering/subagents)).
- Exact remaining conditions: establish host-bound root identity at the MCP writer, validate JSON/YAML export against the pinned host, and explicitly opt into denial-framed notices. Root-only scope is necessary until child attribution is established; no generic per-request gate or automatic continuation is required.

## Cursor editor / CLI: measured MVP blocked

- Measurement: `preCompact` input is a host snapshot (`trigger`, `context_usage_percent`, `context_tokens`, `context_window_size`, `message_count`, `messages_to_compact`, `is_first_compaction`), observational only, cannot block or reschedule ([hooks](https://cursor.com/docs/hooks)). It cannot calibrate pre-first-compaction state. Tool-boundary delta accumulation (`postToolUse`/`postToolUseFailure` tool I/O, keyed by `conversation_id`/`generation_id`, persisted to hook state dir) misses initial/system/user/assistant content, so it is not a whole-window estimator. No exact wire-count claim: the snapshot is a host reading, and `model_params` `context` values are an unverified window hint.
- Injection: `sessionStart` / `postToolUse` return `additional_context`; `stop` return `followup_message` EXTENDS the run (loop limit default 5), the inverse of ending it; no hook abort/terminate ([hooks](https://cursor.com/docs/hooks)).
- Tool registration: hooks are spawned scripts (command or prompt type), merge deny > ask > allow, fail open by default (`failClosed:true` opt-in); no per-model gate. Model-callable handover + reader needs an out-of-band MCP server; hook scripts write the file and inject the read directive. That bridge is the main cost driver.
- Storage/reader: hook-local file I/O is demonstrated (`.cursor/hooks/state/` metrics pattern in official docs); transcript file format (`transcript_path`, `agent-transcripts/`, `state.vscdb`) is uncontracted and MUST NOT be parsed ([hooks](https://cursor.com/docs/hooks)).
- Continuation: editor users can start a fresh chat with a stored reader reference; a separate fresh CLI run can receive the same file/reference. CLI `resume` / `--continue` / `--resume` resume history, not fresh-context rollover. A hook-spawned detached run is unverified and claims no UI switch; no third-party open/focus API was found ([CLI overview](https://cursor.com/docs/cli/overview), [using agent in CLI](https://cursor.com/docs/cli/using)).
- Editor vs CLI: hooks are documented for editor Agent Chat (and command-only cloud agents, which skip `sessionStart`); CLI hook support is UNVERIFIED and MUST NOT be assumed from the editor surface.
- Subagents: `subagentStart`/`subagentStop` carry parent linkage plus `agent_transcript_path`; `followup_message` is consumed only when status is completed ([hooks](https://cursor.com/docs/hooks)).
- Exact unblock: a verified active-request/transcript estimator before compaction, or a measurement event that can postpone compaction for the active model to author its handover. `preCompact` alone cannot guarantee authorship before context loss. MCP caller binding also needs design; editor tool hooks do not establish CLI hook support. Storage-only manual handover is not a measured pre-compaction adapter.

## Roo Code / Aider CLI

- Roo Code: discontinued and archived (shutdown 2026-05-15); prior-art row (rules/modes only, slider + condensing, no hooks) is confirmed, not overturned. Model-invoked `new_task` subtask delegation is internal delegation, not an installed hook surface. No MVP adapter is worth building; any follow-up belongs to forks (ZooCode/Cline), unsurveyed here ([sunset](https://github.com/RooCodeInc/Roo-Code-Docs/blob/main/docs/sunset.md), [condensing](https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing)).
- Roo mechanisms remain UI/config only: condensing threshold/progress measurement, static rules/custom condensing prompt injection and history/resume storage; MCP could supply writer/reader files, but no measured hook connects them. A maintained fork with a measurement/injection extension surface, not another mode or checkpoint, would justify reassessment.
- Aider CLI: still no installed plugin or hook surface and no installed subagent surface. `/tokens` is manual display (estimates, never enforced limits); `--analytics-log` JSONL is lagged out-of-band, not an in-harness trigger; conventions files are static content; history files (`--chat-history-file`, `--restore-chat-history`, `--save`/`--load`) give durable storage plus manual `/clear` continuation only. No first-party surface exists for registering model-callable handover/reader tools. The Python `Coder` API is explicitly unsupported/unstable scripting surface and MUST NOT be counted as installed plugin support ([token limits](https://aider.chat/docs/troubleshooting/token-limits.html), [options](https://aider.chat/docs/config/options.html), [conventions](https://aider.chat/docs/usage/conventions.html), [scripting](https://aider.chat/docs/scripting.html)).
- Aider's exact unblock is a supported extension/hook that observes current request content or usage, injects a notice, and registers writer/reader actions. Manual clearing is already sufficient continuation; a session-launch API is not required. A wrapper/fork is a different deliverable, with high effort relative to Pi/Crush and no current adapter recommendation.

## Quick screen: Kilo, Qwen, OpenHands, Zed, Warp, Kiro

- Kilo Code: highest fast-track assessment candidate. Source-backed on measurement: per-message `AssistantMessage.tokens` (`input`/`output`/`reasoning`/`cache`) and `Session.tokens` fields exist in the pinned SDK types - but aggregation semantics are unverified from the declarations, so neither is claimed as a cumulative anchor. Injection (`experimental.chat.messages.transform`, `experimental.chat.system.transform`, `experimental.session.compacting`) and custom-tool handover surface stand from the docs read ([plugins](https://kilo.ai/docs/automate/extending/plugins)). Caveat: the upstream plugin contract is a legacy lineage match, not a verified V2 direct port; payload schemas, exact subagent event names, and programmatic new-session + seed + UI-switch rotation remain unverified. Do not claim the cheapest full adapter or exact subagent events before that read.
- Qwen Code: follow-up only. Richest screened hook lifecycle (`PreToolUse` deny, `Stop` block, `SessionStart`/`UserPromptSubmit` inject, prompt hooks, `PreCompact`/`PostCompact` with manual/auto matchers, subagent hooks) ([hooks](https://qwenlm.github.io/qwen-code-docs/en/users/features/hooks/)). No hook-readable current-window usage or complete-request estimator verified; cumulative usage would not suffice. Quick screen only, not proven feasible and not ranked above the assessed candidates.
- OpenHands: follow-up only. `PreToolUse` deny, `Stop` block (lint/test gate), `UserPromptSubmit` `additionalContext`, plus SDK plugin packaging ([hooks](https://docs.openhands.dev/openhands/usage/customization/hooks), [SDK plugins](https://docs.openhands.dev/sdk/guides/plugins)). Trigger source (no usage in hook payload found) and hook-initiated rotation are unverified; quick screen only.
- Kiro CLI: follow-up (promising, payload-schema read required). The prior IDE-only "no hooks" reading is invalid for the CLI: primary docs list CLI lifecycle triggers (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, plus `agentSpawn` as a 2.x/V3 alias) with a per-trigger block table (`PreToolUse` can block; `Stop` can request another turn; `UserPromptSubmit` cannot block in CLI V3) ([trigger types](https://kiro.dev/docs/hooks/types/), [CLI hooks migration](https://kiro.dev/docs/cli/v3/hooks-migration/)). Page bodies are thin/secondary-corroborated, so hook payload schema (usage? caller identity?) and programmatic continuation stay UNVERIFIED: promising, not blocked-due-to-no-model-gate, and not proven feasible.
- Zed / Warp: deferred. Zed has no tool-use hooks/events for the built-in agent (extensions host external agents via ACP, not injection into Zed's own agent); Warp agent hooks are open feature requests and its agent story hosts third-party CLIs that own their own hooks ([Zed #52688](https://github.com/zed-industries/zed/issues/52688), [Warp #7834](https://github.com/warpdotdev/warp/issues/7834)).
